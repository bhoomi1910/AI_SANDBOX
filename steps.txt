================================================================================
  AEGIS SANDBOX AI  —  SETUP & RUN GUIDE  (steps.txt)
  AI-Powered Interactive Malware Analysis & Threat Investigation Platform
  MSc Cyber Security demonstration prototype
================================================================================

This guide is written for BEGINNERS. Follow it top to bottom.

TL;DR — the fastest way to see the app (no backend, no database needed):
    1) Install Node.js 20
    2) Open a terminal in the "frontend" folder
    3) Run:  npm install
    4) Run:  npm run dev
    5) Open  http://localhost:5173  and click "Access console"

That's it — the whole workflow runs on built-in realistic mock data.
The backend, database, Docker and sandbox below are OPTIONAL and only needed
if you want to demonstrate the full production topology.


================================================================================
  0. WHAT YOU WILL RUN
================================================================================

  • FRONTEND  — the SOC console (React). REQUIRED. This is the demo.
  • BACKEND   — FastAPI REST API (Python). OPTIONAL.
  • DATABASE  — PostgreSQL. OPTIONAL (backend defaults to SQLite).
  • REDIS     — task broker. OPTIONAL (production topology only).
  • SANDBOX   — CAPE/Cuckoo. OPTIONAL (results are simulated in the prototype).

--------------------------------------------------------------------------------
  Open PowerShell and run:

    winget install OpenJS.NodeJS.LTS

    curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
    sudo apt-get install -y nodejs

  3. RUN THE FRONTEND  (this is the main demo)  ✅ REQUIRED

    npm run build               # type-checks + bundles into frontend/dist
    npm run preview             # serves the production build


================================================================================
  4. RUN THE BACKEND  (optional — FastAPI)
================================================================================
  The backend runs on SQLite by default, so NO database setup is required.

  Windows (PowerShell):
    cd backend
    python -m venv .venv
    .\.venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    copy .env.example .env
    uvicorn app.main:app --reload --port 8000

  Linux/macOS:
    cd backend
    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    cp .env.example .env
    uvicorn app.main:app --reload --port 8000

  Open the interactive API docs:   http://localhost:8000/docs
  Health check:                     http://localhost:8000/api/health

  (IMPORTANT: install into the virtual environment as shown. Installing the
   pinned versions globally on top of other packages can cause version clashes.)

  To have the FRONTEND call the backend instead of local mock data:
    - In frontend/.env set:  VITE_USE_BACKEND=true
    - Restart  npm run dev
    (Leaving it false keeps the demo fully self-contained — recommended.)


================================================================================
  5. RUN THE DATABASE  (optional — PostgreSQL, only without Docker)
================================================================================
  Easiest is Docker (section 7). If you want a local PostgreSQL:

    1) Create the database and user:
         psql -U postgres
         CREATE USER aegis WITH PASSWORD 'aegis';
         CREATE DATABASE aegis OWNER aegis;
         \q

    2) Load the schema:
         psql -U aegis -d aegis -f database/init.sql

    3) Point the backend at it — in backend/.env set:
         DATABASE_URL=postgresql+psycopg2://aegis:aegis@localhost:5432/aegis

    4) Also uncomment  psycopg2-binary  in backend/requirements.txt and reinstall.


================================================================================
  6. REDIS  (optional — production task queue)
================================================================================
  Only needed for the Celery/async topology (not required for the demo).
    - Docker:   handled automatically by docker-compose (section 7)
    - Local:    start the redis-server service, then in backend/.env:
                  REDIS_URL=redis://localhost:6379/0


================================================================================
  7. RUN EVERYTHING WITH DOCKER  (optional — full stack in one command)
================================================================================
  Make sure Docker Desktop is running, then from the project root:

    docker compose up --build

  Services that start:
    • frontend  → http://localhost:8080
    • backend   → http://localhost:8000/docs
    • db        → PostgreSQL on localhost:5432 (schema auto-loaded)
    • redis     → localhost:6379

  Rebuild after code changes:   docker compose up --build
  Run in background:            docker compose up -d --build
  View logs:                    docker compose logs -f


================================================================================
  8. START THE SANDBOX  (optional — CAPE / Cuckoo)
================================================================================
  The prototype SIMULATES sandbox detonation, so this is NOT required.

  For a real deployment you would:
    1) Provision a CAPE Sandbox (recommended) or Cuckoo host with a Windows VM.
    2) Expose its REST API (default CAPE: http://<host>:8000/apiv2/).
    3) Add the connector settings to backend/.env, e.g.:
         SANDBOX_URL=http://localhost:8000/apiv2/
         SANDBOX_API_TOKEN=...
    4) Replace the simulated results in app/data/mock_data.py with live calls.
  See: https://capev2.readthedocs.io/  and  https://cuckoo.readthedocs.io/

================================================================================
  13. COMMON TROUBLESHOOTING
================================================================================

  Q: "npm install" fails or is slow.
  A: Ensure Node.js 20 (node -v). Delete node_modules and package-lock.json,
     then run  npm install  again. Behind a proxy? configure npm proxy settings.

  Q: Port 5173 (or 8000/8080/5432) is already in use.
  A: Something else is using it. Stop that app, or change the port:
       Frontend: npm run dev -- --port 5174
       Backend:  uvicorn app.main:app --reload --port 8001

  Q: PowerShell: "running scripts is disabled" when activating the venv.
  A: Run once in an elevated PowerShell:
       Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
     Then re-run  .\.venv\Scripts\Activate.ps1

  Q: Backend errors like "unexpected keyword argument 'on_startup'".
  A: You installed into a global environment with clashing library versions.
     Always use the virtual environment (section 4) so the PINNED versions in
     requirements.txt are used. Recreate it:
       Windows:  rmdir /s /q .venv  &&  python -m venv .venv
       Linux:    rm -rf .venv       &&  python3 -m venv .venv

  Q: Python 3.14 gives dependency errors.
  A: Use Python 3.12 (or 3.11). Some libraries do not yet ship wheels for 3.14.

  Q: "docker compose" says the daemon is not running.
  A: Start Docker Desktop first and wait until it says "Engine running".

  Q: The map / charts look empty for a second.
  A: That's the loading animation — data renders immediately after. Refresh if needed.

  Q: Blank page after login.
  A: Hard-refresh (Ctrl+Shift+R). Ensure you opened http://localhost:5173 (not file://).

  Q: PDF export.
  A: On the Report page click "Export PDF" — it opens the browser print dialog;
     choose "Save as PDF". The report is print-styled (sidebar/topbar hidden).
